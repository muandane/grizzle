# Combining Grizzle with `sqlc` 🐻 🤝 ⚡

One of the most powerful workflows enabled by Grizzle is pairing it with **[sqlc](https://sqlc.dev/)** (which compiles SQL queries into type-safe Go code).

## The Dual-Source Problem (Before Grizzle)

Normally with `sqlc`, you have two conflicting worlds:
1. Migration files: `0001_init.up.sql`, `0002_add_cols.up.sql`, `0003_fix.up.sql`, etc.
2. `sqlc.yaml`: Needs to parse all up-migration files or an exported schema file.
3. Every Git merge branch risks out-of-order sequence numbering or migration drift.

## The Grizzle + `sqlc` Solution (Single Source of Truth)

With Grizzle, you maintain a single `schema.sql` at the root of your project:

```
my-app/
├── db/
│   ├── schema.sql      <-- Single source of truth for BOTH sqlc and Grizzle
│   ├── queries.sql     <-- Hand-written application queries
│   └── models.go       <-- Generated by sqlc
├── main.go             <-- Embedded Grizzle.Sync() at startup
└── sqlc.yaml           <-- Points directly to schema.sql
```

### 1. `sqlc.yaml` Configuration

```yaml
version: "2"
sql:
  - engine: "postgresql"
    schema: "db/schema.sql"
    queries: "db/queries.sql"
    gen:
      go:
        package: "db"
        out: "db"
        sql_package: "pgx/v5"
```

### 2. In `main.go`

```go
package main

import (
	"context"
	"database/sql"
	_ "embed"
	"log"

	_ "github.com/jackc/pgx/v5/stdlib"
	"github.com/yourorg/grizzle"
)

//go:embed db/schema.sql
var schemaSQL string

func main() {
	ctx := context.Background()
	db, err := sql.Open("pgx", "postgres://localhost:5432/myapp?sslmode=disable")
	if err != nil {
		log.Fatal(err)
	}

	// 1. Declarative automigration on boot
	if err := grizzle.Sync(ctx, db, grizzle.Options{SchemaSQL: schemaSQL}); err != nil {
		log.Fatalf("schema sync failed: %v", err)
	}

	// 2. Query with sqlc-generated typesafe functions
	// queries := db.New(dbConn)
}
```

### Benefits
- **Zero migration drift**: Code generator (`sqlc`) and runtime database engine (`Grizzle`) consume the exact same `schema.sql`.
- **Zero sequence conflict**: Teammates add columns or tables directly to `schema.sql`. Git resolves diffs cleanly.
- **Zero build dependencies**: No Docker or CLI needed at runtime.
