# Using Grizzle with sqlc

Pairing Grizzle with [sqlc](https://sqlc.dev/) creates a unified database workflow where application queries and runtime migrations consume the same SQL schema.

## Dual-source problem before Grizzle

Using sqlc typically involves managing two separate representations of the database schema:

1. Numbered migration files (`0001_init.up.sql`, `0002_add_cols.up.sql`).
2. An exported schema dump or parsed migration list in `sqlc.yaml`.
3. Simultaneous branch work causes sequence collisions, drift between the Go models and database tables, and failed CI builds.

## Single source of truth workflow

With Grizzle, you maintain a single `schema.sql` at the root of your project:

```text
my-app/
├── db/
│   ├── schema.sql      <-- Single source of truth for sqlc and Grizzle
│   ├── queries.sql     <-- Application SQL queries
│   └── models.go       <-- Generated by sqlc
├── main.go             <-- Calls grizzle.Sync() at startup
└── sqlc.yaml           <-- Configured to read db/schema.sql
```

### Configuration with `sqlc.yaml`

```yaml
version: "2"
sql:
  - engine: "postgresql"
    schema: "db/schema.sql"
    queries: "db/queries.sql"
    gen:
      go:
        package: "db"
        out: "db"
        sql_package: "pgx/v5"
```

### Application startup in `main.go`

```go
package main

import (
	"context"
	"database/sql"
	_ "embed"
	"log"

	_ "github.com/jackc/pgx/v5/stdlib"
	"github.com/muandane/grizzle"
)

//go:embed db/schema.sql
var schemaSQL string

func main() {
	ctx := context.Background()
	db, err := sql.Open("pgx", "postgres://localhost:5432/myapp?sslmode=disable")
	if err != nil {
		log.Fatal(err)
	}
	defer db.Close()

	// 1. Declarative automigration on boot
	if err := grizzle.Sync(ctx, db, grizzle.Options{
		SchemaSQL: schemaSQL,
		AllowDrop: false,
	}); err != nil {
		log.Fatalf("schema sync failed: %v", err)
	}

	// 2. Query with sqlc-generated typesafe functions
	// queries := db.New(db)
}
```

## Advantages

* **Zero schema drift**: The code generator (`sqlc`) and runtime database engine (`Grizzle`) consume the exact same `schema.sql`.
* **Zero sequence collisions**: Developers add columns or tables directly to `schema.sql`. Git resolves diffs like standard application code.
* **Zero build dependencies**: No Docker or CLI required at application startup.
